# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff_matches_plan | The diff's changed files and hunks read against the plan's approach, files to touch, and scope, plus the plan's deviation notes and any deviation the description discloses | Every behavior-changing hunk carries out a step the plan names, and every step the plan names appears in the diff. A change the plan does not name, a different approach than planned, or a planned step missing from the diff passes only if the plan's deviation notes or the description state what changed and why. Undisclosed extra, missing, or different work fails. | required |
| description_matches_diff | Each claim in the PR title and description about what changed, read against the diff | Every claim is backed by the diff, and every behavior-changing hunk is mentioned or clearly covered by the description. Fails only when a claim is materially wrong: it describes a behavior, fix, test, or scope the diff does not deliver, it omits a behavior change the diff makes, or it claims fidelity to the plan ("implements the plan as written", "no other changes") that the diff contradicts. A loose summary of an accurate change (counting a new helper and its one caller as "one function touched", describing what the tests cover in general terms) is not a mismatch when the diff does what the claim means. | required |
| evidence_is_observable | The test evidence read against the plan's test plan and the repro evidence | The repro steps (or the plan's main test) are re-run on the branch with their actual output shown, and that output differs from the repro evidence's broken result the way the test plan predicts. Every other step in the test plan is reported with a specific result ("prints exactly one value", "renders unchanged") or disclosed as skipped with a reason. Fails if the repro re-run shows no actual output ("tests pass", "verified locally"), if its output matches the broken result, or if a planned step is silently missing. | required |
| repo_checks_run | The test evidence and description read against the checks the repo facts, PR template, or contribution docs ask contributors to run (test suite, lint, format, type check, build, codegen) | Every check the repo asks for is reported with its specific result: the check named (by command or name) and its outcome ("passes (312 tests)", "clean", "no diff", or the failure and its reason). Pasted output is not required for these checks; the repro re-run's output is graded by evidence_is_observable. A requested check that is never mentioned, a blanket claim that names no check ("all checks pass"), or a check deferred to CI fails. A check that fails or could not run passes only if the evidence states the result and the reason honestly. If the repo names no checks, this passes with that fact as evidence. | required |
| diff_is_clean | The diff's hunks and changed file list read against the plan's scope | Every hunk serves the fix. Debug output (print, console.log, logging added only to investigate), commented out code, stray files (plan notes, local configs, scratch scripts, unrelated lockfile churn), and unrelated formatting, renames, or refactors each fail, even when the description mentions them. | required |
| template_followed | The PR description read against the repo facts' PR template and the contribution docs' asks for pull requests (issue reference, required sections, checklists) | If the repo has a PR template, every section has real content (an "N/A" with a reason counts; an empty section or the template's placeholder text does not), and no checkbox is ticked for something the evidence does not show. Every other ask the contribution docs make of a PR (such as referencing the issue) is met. If the repo states no template and no PR asks, this passes with that fact as evidence. | required |
| disclosure_policy_met | The PR description read against the repo facts' AI or disclosure policy and any disclosure the template asks for | If the repo states an AI use or disclosure policy, the description contains the disclosure that policy requires, in the place and form it asks for. A missing disclosure cannot be excused by assuming no AI was used. If the repo states no such policy, this passes with that fact as evidence. | required |
| title_names_change | The PR title read against the diff | The title says what the change does and where ("Skip BM25 build on empty chunk list"), not only that something was fixed ("Fix bug", "Update file"). | preferred |

## Verdict rule

Accept (submit) only if every required check passes. Reject (hold) if any required check fails or is unclear: an unclear required check means the package did not show the evidence, and a PR that cannot show it is not ready to submit. Preferred checks are reported but never change the verdict, whether they pass, fail, or are unclear. A shortfall the package honestly discloses (a skipped test with its reason, a deviation recorded in the plan or description) is graded as passing by the checks that allow it; do not reject a PR only because it does less than everything.
