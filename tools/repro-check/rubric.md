# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| environment-recorded | TThe record lets a reader tell which platform and which code the behavior was seen on: the OS or browser, the versions the bug-report template asks for, and what was tested. A released version number identifies the tested code; a commit or branch is needed only when no release is named. Fail when the platform or the tested code cannot be determined, or when the tested version contradicts the version the issue targets or the version the template asks reporters to test on (such as latest release or main) and the report does not call out the difference. Missing details the template does not ask for, such as a package manager version, do not fail this
| steps-followable | The repro report's steps, read against the issue context and the setup notes in the repo-facts block | A stranger starting from a fresh clone could reach the observed behavior using only these steps, without guessing a command, an input, a URL, or a setup action. Judge whether the steps reach the outcome, never how many there are or how they are formatted | required |
| behavior-matches-issue | The artifacts (output excerpt, error text, screenshot or its description) read against the behavior the issue describes | The artifacts show the behavior the issue describes, on the same page, command, or component. Fail if they show an adjacent bug, a different error, or a setup failure presented as the issue. For a cannot-reproduce outcome, pass when the artifacts show the issue's own steps were run and the correct behavior was observed | required |
| outcome-honest | The report's stated outcome, read against its artifacts | The stated outcome (reproduced, partially reproduced, or cannot reproduce) is exactly what the artifacts support. Fail if it claims a reproduction the artifacts do not show, claims a root cause or fix that was not demonstrated, or says cannot reproduce without showing the attempt. An evidenced cannot-reproduce passes | required |
| conventions-respected | The claim comment and repro report, read against the contribution policy and AI-use policy in the repo-facts block and the house rules in scope.md | The comments follow the repo's stated conventions. Issue comments, including claims and repro reports, count as contributions: a policy that requires disclosing AI use in contributions applies to them. When such a policy exists, the package passes if at least one of its comments discloses AI assistance, since a claim and its report form one contribution, and fails if neither does. Do not excuse a missing disclosure by concluding the author used no AI; a grader cannot observe that, so under a disclosure policy the absence of a disclosure is a fail. When the policy is silent or only asks for human review or responsibility, no disclosure is required. The proof is in the author's own words; a piggyback on another commenter ("same as above", "can confirm") fails | required |
| claim-specific | The claim comment, read against the issue body | The claim names something specific to this issue (the behavior, page, component, or error) and says what the author will do next. Fail only when the claim could be pasted onto any other issue unchanged | required |

## Verdict rule

Accept when every required check passes. A fail on any required check rejects the package. Unclear on a required check counts as a fail, since a stranger cannot act on proof that is not there.

On a claim-only draft with no repro report, environment-recorded, steps-followable, behavior-matches-issue, and outcome-honest report as not yet applicable and do not hold the claim. The verdict then comes from claim-specific and conventions-respected.
